## Hook (3 giây đầu)
"Người tạo ra Claude Code nói: đừng bắt nó code ngay."

## Script voiceover (ElevenLabs-ready)
[Đoạn 1 — vấn đề/pain point]
Mày giao việc cho Claude Code, nó chạy một lúc rồi báo xong. Mày mở ra xem thì sai. Lỗi không nằm ở con AI. Lỗi nằm ở chỗ mày không cho nó cách tự kiểm tra.

[Đoạn 2 — giới thiệu giải pháp]
Boris Cherny, người làm ra Claude Code, có một talk dài hai mươi tám phút. Tao đọc lại, đối chiếu với tài liệu chính thức mới nhất, và rút ra ba thói quen còn đúng đến tận bây giờ.

[Đoạn 3 — demo/cách làm]
Một. Hỏi trước, sửa sau. Mở repo lạ ra, hỏi hàm này dùng ở đâu, vì sao viết như vậy. Nó tự tra lịch sử git cho mày.
Hai. Cho nó cách tự kiểm. Một bộ test, một lệnh build, hay một ảnh chụp màn hình để so. Thiếu cái này thì chính mày là người đi kiểm từng lỗi.
Ba. Giữ file CLAUDE.md thật ngắn. Dài quá thì nó bỏ qua luật của mày. Và nhớ gõ clear giữa hai việc không liên quan.

[Đoạn 4 — kết + CTA]
Lưu ý nhỏ. Talk này từ năm hai ngàn không trăm hai mươi lăm, một số lệnh đã đổi tên. Tao đã cập nhật hết trong một file. Comment chữ kho, tao gửi link.

## Ghi chú quay (OBS)
- Cảnh 1 (0-3s): chữ lớn trên nền tối "Đừng bắt Claude code ngay". Không cần quay màn hình.
- Cảnh 2 (3-15s): quay terminal Claude Code, gõ một câu hỏi về repo, để Claude trả lời. Chỉ hỏi, chưa sửa gì.
- Cảnh 3 (15-35s): chia 3 lần cắt cho 3 thói quen. Thói quen 2: quay lúc Claude chạy test và hiện kết quả xanh/đỏ. Thói quen 3: mở file CLAUDE.md, cuộn cho thấy nó ngắn, rồi gõ /clear.
- Cảnh 4 (35-55s): mở file skill trong kho, cuộn qua bảng "cái đã đổi so với talk" để người xem thấy có cập nhật.
- Quay thật trên máy, không dựng cảnh. Nếu chưa chạy được Claude Code trên máy, dùng ảnh docs thay thế và nói rõ đây là minh hoạ.
